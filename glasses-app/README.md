# PriceLens — identify & price objects on AI glasses

A native **Android XR** app built with
[Jetpack Compose Glimmer](https://developer.android.com/develop/xr/jetpack-xr-sdk/jetpack-compose-glimmer).
Point the glasses at an object; PriceLens identifies it and shows an estimated market
**price in real time** as a heads-up overlay, plus a short list of recently scanned items.

## How it works

```
camera frame ──▶ ObjectRecognizer ──▶ RecognizedObject ──▶ PricingService ──▶ price
                                          │                                      │
                                          └────────── ScannerViewModel ──────────┘
                                                            │
                                                     ScanState (StateFlow)
                                                            │
                                                     ScannerScreen (Glimmer UI)
```

- **`ObjectRecognizer`** emits the object currently in view (or `null` while searching).
- **`PricingService`** resolves an estimated price for a recognised object.
- **`ScannerViewModel`** wires them together and exposes a single `ScanState` + history.
- **`ScannerScreen`** renders the live result as a Glimmer `Card`, with a `VerticalList`
  of recent finds.

The app ships with **real** implementations wired in by default:

- **`MlKitObjectRecognizer`** runs CameraX `ImageAnalysis` frames through ML Kit on-device
  image labeling, publishing a new `RecognizedObject` only when the in-view object changes.
- **`SerpApiPricingService`** queries SerpApi's Google Shopping engine for a live price.

Each is an interface, so **demo fallbacks** (`DemoObjectRecognizer`, `DemoPricingService`)
remain available for offline previews/tests without camera, ML, or network.

## Pricing API key

`SerpApiPricingService` reads `BuildConfig.SERPAPI_KEY`, populated from a Gradle property
so the key never enters source control. Add it to your **global** Gradle properties
(`~/.gradle/gradle.properties`):

```properties
serpApiKey=YOUR_SERPAPI_KEY
```

Without a key, the price card shows "Set serpApiKey to enable pricing" — recognition still
works. Get a free key at serpapi.com, or swap `SerpApiPricingService` for another
marketplace API (eBay, StockX, …) by changing the endpoint and JSON field extraction.

## Going further

- **Finer identity** — the default ML Kit labeler returns generic categories ("Shoe").
  For exact products, train a custom image-labeling model or add a product-search backend
  / barcode scanner; `MlKitObjectRecognizer` is the only file that changes.
- **Caching** — add a short-lived cache in front of `SerpApiPricingService` to avoid
  re-querying the same label.
- **Glasses camera** — on real Android XR hardware, point CameraX at (or replace it with)
  the Jetpack XR camera APIs; the `ObjectRecognizer` seam stays the same.

## Build & run

Standard Android Studio project — needs the latest **Android Studio Canary** for Android XR
preview/emulator support.

1. Open `glasses-app/` in Android Studio and let it sync (Studio generates the Gradle
   wrapper JAR on first sync; from a terminal, `gradle wrapper` with Gradle ≥ 8.10 also works).
2. Preview a screen with `@Preview` + the **AI Glasses** device, or run on an **Android XR**
   emulator image from Device Manager.

Requirements from the Glimmer build guide: `minSdk` 24, `compileSdk` 34+ (this uses 35).

## Notes & caveats

- **Alpha dependencies.** Glimmer/XR libraries (`androidx.xr.*`) are alpha and move fast.
  Versions here match the provided build guide; bump to the newest alpha if a signature
  changed, then re-sync.
- **Not compiled in this environment.** The Android SDK and the alpha Maven artifacts
  aren't available in the container this was authored in, so it hasn't been compiled here.
  Component usage follows the official Glimmer docs, but expect small adjustments on first
  sync (e.g. the exact import path of `createGoogleSansFlexTypography` or a typography
  style name) — Android Studio surfaces these immediately.
